# SQLAlchemy 2.0 and Alembic (my-python-app)

Data-access conventions for this Python project. Use `database-migrations` for
zero-downtime rules; this skill covers SQLAlchemy 2.0 and Alembic commands.

## When to Activate

- Adding or changing SQLAlchemy models
- Writing repositories or session/transaction code
- Creating, reviewing, or applying Alembic migrations

## Model Style (2.0)

```python
from datetime import datetime
from sqlalchemy import DateTime, String, func
from sqlalchemy.orm import Mapped, mapped_column

from app.db.base import Base


class User(Base):
    __tablename__ = "users"

    id: Mapped[str] = mapped_column(String(36), primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    name: Mapped[str] = mapped_column(String(100))
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=func.now()
    )
```

- Use `Mapped[]` + `mapped_column`, not declarative `Column`.
- Put constraints and indexes in the model (or Alembic) — never "we'll add it later".
- Do not expose models from FastAPI handlers; map to Pydantic schemas.

## Session Lifecycle

One request, one session. Commit in the dependency, not in random helpers.

```python
from collections.abc import AsyncIterator
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

from app.core.config import settings

engine = create_async_engine(settings.database_url, pool_pre_ping=True)
SessionLocal = async_sessionmaker(engine, expire_on_commit=False)


async def get_session() -> AsyncIterator[AsyncSession]:
    async with SessionLocal() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
```

Repositories receive an `AsyncSession`. They do not create engines.

```python
class UserRepository:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session

    async def find_by_email(self, email: str) -> User | None:
        result = await self._session.execute(
            select(User).where(User.email == email)
        )
        return result.scalar_one_or_none()

    async def add(self, user: User) -> User:
        self._session.add(user)
        await self._session.flush()
        return user
```

## Query Rules

```python
# PASS: select only what you need; eager-load relations you will touch
stmt = (
    select(Order)
    .options(selectinload(Order.items))
    .where(Order.user_id == user_id)
    .order_by(Order.created_at.desc())
    .limit(20)
)

# FAIL: lazy-load in a loop (N+1)
for order in orders:
    _ = order.items
```

Prefer `selectinload` / `joinedload` at the query site. Do not mute
`MissingGreenlet` by enabling implicit IO.

## Alembic Workflow

```bash
alembic revision --autogenerate -m "add users.avatar_url"
# Review the generated file. Autogenerate misses constraints, data, and
# CONCURRENTLY indexes — edit by hand when needed.
alembic upgrade head
alembic downgrade -1          # local only; production uses a new forward migration
```

Keep schema and data changes in separate revisions. Do not edit a revision
that has already run in any shared environment.

```python
# alembic/versions/20260914_add_user_avatar.py
def upgrade() -> None:
    op.add_column("users", sa.Column("avatar_url", sa.Text(), nullable=True))


def downgrade() -> None:
    op.drop_column("users", "avatar_url")
```

For large tables: add nullable columns, backfill in batches, then add
constraints. See `database-migrations` for expand-contract.

## Safety Checklist

- [ ] Model uses SQLAlchemy 2.0 typing (`Mapped` / `mapped_column`)
- [ ] Session is request-scoped; commit/rollback lives in one place
- [ ] Unique/index constraints exist for lookup columns
- [ ] Autogenerated migration was reviewed (not blindly applied)
- [ ] New columns are nullable or have a server default
- [ ] No raw SQL with string-interpolated user input
